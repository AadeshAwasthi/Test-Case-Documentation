# Test Case Template

| Field | Description |
|---|---|
| **TC ID** | Unique ID, e.g. TC_001 |
| **Module** | Feature or module under test |
| **Title** | Short one-line summary of what is being verified |
| **Type** | Functional / Negative / UI / Regression / Smoke / Compatibility |
| **Priority** | High / Medium / Low |
| **Precondition** | What must be true before starting |
| **Test Data** | Input values used |
| **Steps** | Numbered steps, one action per step |
| **Expected Result** | What should happen |
| **Actual Result** | What actually happened (filled during execution) |
| **Status** | Pass / Fail / Blocked / Not Run |

## Tips for writing good test cases

1. One test case should verify one thing.
2. Steps should be clear enough for a new tester to follow.
3. Expected result must be specific and measurable.
4. Cover positive, negative and boundary conditions.
5. Keep test data separate so it can be changed easily.
